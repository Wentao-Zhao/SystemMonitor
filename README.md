# SystemMonitor

独立编写的原生 macOS 菜单栏监控工具。近期目标是替代当前机器上 iStat Menus 的核心用途，当前交付为 0.1.0 开发预览。工程没有 fork、复制或改造开源监控应用。

## 当前功能

- 默认合并菜单栏，可切换为各模块独立显示；两种模式分别记住指标显隐、顺序和摘要样式。
- CPU 整机、逐核心、性能核/能效核平均负载。
- GPU 设备忙碌率。
- 内存已用/可用、压缩、缓存、交换空间和系统压力等级。
- 本地卷容量、剩余空间和对应物理设备读写速率。
- 指定网卡或自动主要网卡的上下行速率及本次应用会话流量。
- CPU/GPU 热区最高温和逐热区读数、实际风扇 RPM。
- GPU 与整机功耗；CPU 分项功耗在系统提供有效数据时显示。
- 1/5/15 分钟曲线，暂停/继续、1/2/5 秒基础刷新、登录时启动。

不包含电量、充电状态或手动风扇调速。所有数据留在本机；不需要账号，不上传监控数据。

## 已验证与未满足项

优先验证设备：Apple M1 Pro MacBook Pro、32 GB、macOS 27.2.1。工程最低部署版本是 macOS 14，不代表已经完成所有系统和机型的兼容性测试；Intel 尚未验收。

**CPU 分项功耗尚未满足完整替代要求。** 当前机器的系统 CPU 能量计数在受控负载下仍不变化。应用将其显示为不可用，不把冻结计数当作 0 W，不从整机功耗猜测 CPU 功耗。GPU 功耗与整机功耗可以独立读取。证据见 [硬件验证记录](docs/hardware-validation.md)。

温度来自芯片热区；编号不对应某一个物理核心。风扇在静止时的 0 RPM 是真实数据。整机功耗来自 SMC 传感器，既不是 CPU/GPU 分项之和，也不是插座交流电功耗。

系统内存压力显示系统提供的正常/偏高/紧张等级，不是活动监视器内存压力曲线的精确重绘。内存已用按 VM 页统计推导，扣除文件缓存与可清理页；应对齐采样时间及口径再作比较。

磁盘可用空间不包含额外推测的可清理容量；APFS 共享容器的卷容量不累加。读写属于底层设备，可能包含该设备上其他卷的 I/O。网络只统计一个网卡，VPN 不与物理接口累加；流量计数在重启或切换网卡后归零。

## 安装与使用

构建产物在 `dist/SystemMonitor.app` 和 `dist/SystemMonitor-0.1.0.dmg`。打开 DMG，将 App 拖入 Applications 后启动。

- 左键菜单栏打开概览或对应模块详情；右键可打开设置、暂停或退出。
- 首次启动展示设置；也可从设置中的“查看监控概览”打开独立窗口，在菜单栏空间不足时继续使用。重新打开 App 可找回设置窗口。
- 在设置切换合并/独立模式，勾选摘要、调整顺序和样式，选择网卡、磁盘、温度或功耗摘要。
- 摘要显隐只影响菜单栏，概览与详情仍采集所有模块。全局暂停才停止采集；详情会标明保留的数据。
- 硬件最快每 2 秒读取；基础数据按所选 1/2/5 秒间隔采样；磁盘容量每 30 秒刷新。
- 不可用指标显示破折号；存在历史有效值时详情显示上次数据及时间，曲线留空。
- 登录时启动默认关闭，需在设置主动开启；系统要求批准时提供登录项设置入口。

当前应用采用临时本机签名，尚无 Developer ID 签名/公证。首次打开如被系统拦截，请查看“系统设置 → 隐私与安全性”的相应提示。此开发预览没有自动更新或 App Store 分发。

## 构建与检查

需要 macOS 上的 Swift 6 工具链及 Command Line Tools。应用自身使用 Swift 5 语言模式，无第三方包依赖。

```sh
zsh scripts/test.sh
zsh scripts/package-app.sh
zsh scripts/package-dmg.sh
```

真实数据诊断（复用正式采集器，默认 3 个采样）：

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-cache" swift run --disable-sandbox \
  --cache-path .build/swift-cache --config-path .build/swift-config \
  --security-path .build/swift-security MonitorProbe 3
```

AppleSMC 与 IOReport 会受到命令执行沙盒限制。应在普通终端或正常启动的 App 中验证；不需要 sudo，不安装特权助手。第一笔速率/功耗采样只建立基线。硬件访问使用只读调用，未暴露风扇写入能力。

硬件错误类别与失败码通过本地统一日志记录，子系统为 `local.wentao.SystemMonitor`，类别为 `Hardware`。界面只展示用户可理解的状态；日志不包含流量内容、用户文件路径或上传数据。

## 工程结构

`MonitorCore` 管理模型、差分、历史和偏好；`SystemCollectors` 负责系统数据；`HardwareBridge` 隔离只读底层接口；`SystemMonitor` 负责 AppKit 菜单栏和 SwiftUI 界面。基础采集和硬件采集使用不同后台队列，主线程更新界面。

温度和功耗接口不是稳定的公开应用 API，需要按 macOS 和芯片继续验证；错误不能降级成虚构的正常数据。完整规格及实现步骤位于 `docs/superpowers/`。
