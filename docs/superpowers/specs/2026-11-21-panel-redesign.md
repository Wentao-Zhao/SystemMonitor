# 状态栏弹窗重设计与悬停提示移除

## 本轮需求与范围

用户要求移除状态栏鼠标悬停后的大段读数提示，并重新设计点击后的 UI。保留现有点阵、逐指标配置、采集器及磁盘容量修复。

## 最终设计

- 状态栏按钮所有渲染路径均设 `toolTip = nil`，丰富读数仅用于 VoiceOver 的 accessibility label。
- 弹窗与独立概览共享 480×610 的原生 SwiftUI 面板。顶部为应用标识、实时/暂停状态、独立窗口和设置入口。
- 固定模块导航：概览、CPU、GPU、内存、磁盘、网络、传感、功耗。
- 概览首屏突出 CPU 历史与内存占用，网络上下行并排、磁盘容量横向排列；GPU、温度与整机功耗放入次级区域。
- 统一原生字号、低对比表面、细边框与绿色基调；橙/红色仅表达状态。不使用原来的大图标、口号和每模块一种颜色。
- 详情保留全量读数、1/5/15 分钟历史、固定百分比上限、缺测分段、历史有效值和过期时间。网络历史使用柱形。
- 切换模块时重建 ScrollView identity，从列表底部切换后回到模块顶部。暂停保留最后采样，恢复后允许重新建立数据基线。

## 文件

- `MonitorViews.swift`：面板布局与模块页面。
- `MonitorComponents.swift`：统一表面、计量条、历史曲线和网络柱形。
- `MenuBarController.swift`：去 Tooltip、保留无障碍标签、统一面板尺寸。
- `Tests/MonitorAppTests/main.swift`：Tooltip nil 回归与现有操作检查，读数断言改用 AX label。

## 验证

- 新增检查先在旧实现复现两个失败：正常与暂停状态均仍有悬停提示。
- 修改后 18 项原生应用检查通过，读数与压力继续通过 AX label 提供。
- Release 构建及已安装应用签名验证通过，已备份并更新 `/Applications/SystemMonitor.app`。
- CUA 实际验证独立窗口概览、CPU 十五分钟切换、长列表滚动后切内存回到顶部、网络柱形、暂停/恢复。
- 最后从系统菜单栏宿主实际点击 SystemMonitor，确认新版 NSPopover 打开且首屏布局完整。
- 原生模块入口、用户原有五项状态栏选择与采样配置保持原样。
