# 原生 macOS 系统监控应用设计

日期：2026-11-21

## 1. 产品目标与已确认决策

近期目标是在用户的 Mac 上替代 iStat Menus 的核心监控用途；远期目标是逐步成为可分发、可维护的完整产品。

- 独立开发 Swift 原生应用，不 fork 开源监控应用，不复制其实现。系统官方文档与公开研究仅用于理解接口和行为。
- 支持合并菜单栏和模块独立菜单栏两种模式，首次启动默认合并。
- 第一版包含 CPU、GPU、内存、磁盘、网络、温度、风扇转速和功耗。
- 本版不包含电量、充电状态、手动风扇控制。
- 中文界面，支持刷新间隔、指标显隐和开机启动。
- 工作目录及工程暂名为 `SystemMonitor`，不是已确定的产品品牌。

## 2. 支持范围与分发

首要验收设备是当前 MacBook Pro，M1 Pro、32 GB 内存、macOS 27.2.1。第一版面向 Apple Silicon，工程最低部署版本设为 macOS 14；只有实际验证过的机器和系统才声明支持。Intel 和其他 Apple Silicon 型号的验证属于后续产品化工作。

以本地 `.app` 和 DMG 为首版交付形式。Developer ID 签名、公证、自动更新和 App Store 分发在对应发布阶段处理，本设计不承诺 App Store 可接受所有硬件采集方式。应用不需要账户、云服务或远程数据上传。

## 3. 功能与指标口径

| 模块 | 首版详情 | 菜单栏可选摘要 |
| --- | --- | --- |
| CPU | 整机使用率、各逻辑核心负载、性能核/能效核分组、近期曲线 | 整机百分比、微型曲线 |
| GPU | GPU 名称、驱动暴露的设备忙碌率、近期曲线 | 百分比、微型曲线 |
| 内存 | 物理总量、已用、可用、压缩、交换空间、内存压力、近期曲线 | 使用率或已用容量 |
| 磁盘 | 已挂载本地卷的容量和可用空间、物理设备读写速率、近期曲线 | 选中设备读写速率或卷可用空间 |
| 网络 | 网卡列表、网卡选择、上下行速率、本次应用会话收发量、近期曲线 | 上下行速率 |
| 传感器 | CPU/GPU 可识别热区温度、最高温度、各风扇 RPM | 选中温度或风扇转速 |
| 功耗 | CPU/GPU 功耗；硬件实际暴露时额外提供整机功耗 | 选中的功耗值 |

CPU 使用率统一为整机 0–100%，各核心各自为 0–100%。GPU 使用率明确表示驱动提供的忙碌比例，不解释为 GPU 所有计算单元利用率。

内存按页统计及对应分类推导，界面清楚区分可回收缓存、已用和压缩，避免将缓存直接视为内存耗尽。内存压力采用可获取的系统压力信号；不能获取时显示不可用，不自行伪造系统压力值。

APFS 卷共享容器空间，不将各卷容量相加为整机容量。容量显示文件系统当前可用空间，不混同包含可清理空间的可用容量口径。读写速率归属物理设备，不把同一 APFS 容器的 I/O 重复计入多个卷。

网络默认选择当前主要路由对应的接口，只统计所选接口；用户可以指定网卡。VPN 与物理网卡不自动累加，避免重复统计。网卡不存在或断开时显示相应状态；切换接口重置会话计数和该曲线。

网络会话量从启动或切换网卡时开始计算，重启应用后归零。第一版不承诺跨重启月度账单统计。磁盘容量只统计本地存储，网络卷不进入默认列表。

温度传感器代表热区，不将热区编号标成具体 CPU 核心编号。CPU/GPU 功耗属于分项功耗，不能直接相加并标为整机功耗。整机传感器不可用时不显示估算的整机值。

## 4. 菜单栏与窗口交互

### 合并模式（默认）

使用一个状态项，默认紧凑显示 CPU 使用率、内存使用率和上下行网速。用户能选择显示其他指标，并通过设置中的排序控制调整顺序。菜单栏只显示用户勾选的摘要；所有模块可在详情面板查看。

左键点击展开统一面板：顶部为概览，主体按 CPU、GPU、内存、磁盘、网络、传感器与功耗展示分组。点击模块进入其详情，通过返回按钮回到概览。右键菜单提供设置、暂停/恢复采集和退出。

### 独立模式

每个启用的模块拥有独立状态项，点击打开对应模块的详情。用户能独立开关各模块，至少保留一个入口。切换模式立即生效，不重新启动采集、不清除历史、不遗留旧状态项或定时器。两种模式的摘要偏好分别保存。

### 设置与外观

设置包含显示模式、模块显隐、摘要样式、网卡/磁盘选择、刷新间隔和开机启动。默认随系统浅深色模式，不显示 Dock 图标；通过菜单栏进入设置。开机启动默认关闭，由用户主动开启。

第一版使用系统字体、语义颜色和原生控件。曲线支持最近 1、5、15 分钟，默认 5 分钟；横轴按实际时间绘制。暂停、休眠和数据不可用期间留空，不能连线形成虚假的持续采样。

## 5. 架构与数据流

技术栈为 Swift、SwiftUI、AppKit、Mach、IOKit 和必要的窄范围 C 接口桥接；不引入 Electron 或网页容器，不 fork 其他监控工程。

模块划分：

1. `MonitorCore`：指标类型、可用状态、计数器差分、历史缓冲、配置和菜单栏显示策略，独立于 UI 和硬件。
2. `SystemCollectors`：CPU、内存、磁盘、网络、GPU、传感器、功耗的独立采集器，以及系统休眠唤醒观察。
3. `MonitoringStore`：统一调度、最新快照、历史存储和能力状态；只持有一套采样任务。
4. `SystemMonitor`：AppKit 状态项管理、SwiftUI 统一面板/模块详情/设置、启动项服务和应用生命周期。

数据流为：系统接口 → 采集器 → 带时间戳与状态的快照 → 内存中的历史缓冲 → 菜单栏与详情界面。硬件采集在后台串行队列或 actor 执行，UI 更新在主线程执行；慢采集器不得阻塞其他模块。

基础监控优先使用系统接口；GPU 从可用的 IOKit 驱动统计读取。温度和风扇首先验证 SMC 只读路径，功耗首先验证 IOReport 能量计数差分。非公开接口集中在采集边界，便于随系统版本替换。禁止通过每秒启动 shell 子进程维持监控。

第一版不预装特权常驻助手。若核心硬件指标必须依赖额外权限或助手，先记录真实失败原因和可行实现，将其作为设计变更处理；不能静默安装助手，也不能以固定假数据交付。

## 6. 调度、历史与异常

基础刷新支持 1、2、5 秒，默认 2 秒。温度、风扇和功耗采集不快于 2 秒；磁盘容量默认每 30 秒更新。关闭的非依赖模块停止采样，历史使用有界内存缓冲，最多保留最近 15 分钟。

速率使用单调时钟与连续计数器差分计算。首次采样只建立基线，计数器回退或设备更换时重建基线，不产生负速率。唤醒后重建速率和功耗基线，不将休眠期间的累计量算作瞬时峰值。系统休眠时停止调度，恢复后重新发现设备和传感器。

每个指标具有明确状态：等待采样、正常、暂时失败、不支持、权限不足、暂停。真实 0 与无数据不同。采样失败立即标记不可用；保留的上次值在详情中显示时间和过期状态，菜单栏不将旧值伪装为实时数据。

配置保存在本地。第一版历史不落盘。应用日志记录错误类别与接口失败码，不记录网络流量内容、用户文件路径或上传硬件信息。

## 7. 实现顺序

1. 硬件验证：在当前机器读取 GPU 忙碌率、CPU/GPU 温度、风扇 RPM、CPU/GPU 功耗，并记录接口、单位、可用状态和采样成本。这是进入完整 UI 实现前的风险检查点。
2. 实现统一快照、速率计算、历史缓冲、基础采集与硬件采集。
3. 完成默认合并状态项与统一详情面板，让全部模块形成可运行闭环。
4. 增加独立状态项、设置持久化、暂停/恢复、休眠处理和开机启动。
5. 实机对照、资源占用检查、应用与 DMG 打包。

硬件验证若存在缺口，基础模块仍可继续开发；但当前机器上缺少首版要求的硬件指标时，必须明确报告，不能将“显示不可用”视为完整替代目标已达成。

## 8. 验证与完成标准

- 自动化验证覆盖计数器差分、首次采样、计数器回退、接口切换、休眠后基线重建、有界历史、数据缺口和配置恢复。
- 模式切换逻辑验证状态项数量与采集任务数量，保证切换后没有重复采集或遗留入口。
- 当前 Mac 上所有约定模块均显示真实数据；GPU、温度、风扇及 CPU/GPU 功耗必须通过实机验证。整机功耗仅在真实硬件传感器可用时展示。
- 同机同时对照活动监视器、iStat Menus 和系统磁盘/网络统计，在空闲与受控负载下观察至少 10 分钟。对齐刷新窗口后检查单位、负载趋势和数量级；记录接口与统计口径造成的差异，不要求不同统计口径的瞬时值完全相等。
- 在合并与独立模式中验证显示开关、排序、深浅色、弹窗关闭、配置重启恢复、网卡切换、磁盘移除、暂停/恢复及休眠唤醒。
- 默认刷新、关闭详情面板时连续观察资源占用，目标为进程平均 CPU 不超过单个逻辑核心的 1%，常驻内存低于 150 MB；以实测记录判断，超标时分析并优化。
- 本地构建和自动化检查通过，交付可启动的 `.app`、可安装的 DMG 与操作说明；如未签名或未公证，交付说明必须准确注明。

## 9. 本版之外

电池电量、充电状态、手动风扇调速、天气、世界时钟、逐进程监控、远程监控、云同步、长期磁盘历史、自动更新、付费系统，以及未经测试的全机型兼容声明，均不属于本版验收范围。
